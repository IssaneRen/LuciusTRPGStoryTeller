# AI Agent 工作流

## 核心模式: Orchestrator-Workers

```
用户需求
    │
    ▼
┌─────────┐
│  Leader  │  判断复杂度 → 调度或自行完成
└────┬────┘
     │ 拆分任务
     ▼
┌────────────────────────────────────┐
│  Workers (并行)                     │
│  ┌────────┐ ┌────────┐ ┌────────┐ │
│  │Backend │ │  Web   │ │   QA   │ │
│  │  Dev   │ │  Dev   │ │        │ │
│  └────────┘ └────────┘ └────────┘ │
└────────────────────────────────────┘
     │ 产出汇总
     ▼
┌──────────────┐
│  Consultant  │  技术审查
└──────────────┘
     │ 通过/打回
     ▼
   合并交付
```

## 任务生命周期

1. **需求输入** — 用户描述需求或 PM 输出 PRD
2. **复杂度评估** — Leader 判断: 简单/中等/复杂
3. **任务拆分** — 复杂任务分解为原子子任务
4. **并行开发** — Workers 独立执行，互不阻塞
5. **质量验证** — QA 编写测试，Consultant 审查
6. **集成交付** — 合并代码，更新文档

## 上下文管理策略

- 每个 Agent 专注自己的领域文件，不读无关代码
- 大任务完成后清理上下文 (`/clear`)
- 研究类任务用 subagent 隔离，只返回结论
- 知识沉淀到 knowledge/ 目录而非对话记忆

## 敏捷节奏

- **迭代周期**: 1-3 天一个小功能闭环
- **定义完成**: 代码 + 测试 + 文档索引更新
- **回顾优化**: 踩坑结论写入对应 Agent 提示词
